# QXtrl 第一次讨论会决策清单

**版本**: v0.1  
**日期**: 2026-06-02  
**用途**: 第一次 QXtrl 重构规划讨论会使用。目标不是继续扩展想法，而是把开发起跑线拍薄、拍准、拍硬。  

## 1. 会议目标

本次会议结束时应形成四类结论：

1. **统一语言**：确认 3+1 产品架构视图和 L0-L9 权威层号。
2. **冻结 Demo**：确认 1-2 个月内的最薄垂直切片和 OUT 清单。
3. **拍板关键契约**：确认 PulseIR、节点关系、关联层、数据边界、测试硬门等首批契约。
4. **分配 owner**：每个 P0 决策必须有负责人和完成日期。

## 7. 会后必须形成的输出

会议结束后 24 小时内应形成：

1. 已确认的决策表，替换本文中的“待定”。
2. MVP Demo 范围冻结版。
3. P0 contract patch owner 表。
4. 6-8 周开发排期。
5. 旧文档层号迁移计划。

## 8. 建议现场判断标准

如果某个议题无法在 5 分钟内形成结论，按以下规则处理：

1. **影响 Demo 范围**：必须现场拍板。
2. **影响 schema 兼容性**：必须指定 owner 和 3 天内截止日期。
3. **长期架构偏好**：不阻塞 Demo，进入 backlog。
4. **真实硬件相关但 Demo 不需要**：标记为 MVP 后议题。

## 9. 本次会议的底线

本次会议不应继续扩大范围。若新增想法不能服务于 Rabi 最薄闭环、契约稳定或风险消减，应进入后续 backlog，而不是进入 Demo 完成定义。
